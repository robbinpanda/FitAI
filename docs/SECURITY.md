# 安全设计与边界

## 账号隔离

真实入口始终初始化账号系统。所有业务 GET / POST（包括照片、导出、聊天、后台任务）均要求会话；只有静态页面、健康检查和认证入口公开。随机 128 位用户 ID 决定目录，客户端不能指定数据库路径。

每个账号一份 SQLite 与照片目录。请求通过 ContextVar 选择数据路径，线程池任务显式复制上下文，任务查询和取消校验归属。用户请求按账号加锁防止导入与写入交错。首次访问初始化或迁移该用户数据库。旧的单用户数据库不会归属首个注册者。

本地模式不是免登录模式，只是无需邀请码且只能在回环地址运行。服务器模式由环境配置指定；不会根据 Host、来源 IP、X-Forwarded-* 自动降级。生产 WSGI 入口未初始化账号时返回 503。

## 密码、邀请码和会话

- 密码和邀请码使用随机盐 scrypt（N=16384、r=8、p=5，32 字节输出），不是可逆加密；参数参考 [OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)。
- 密码要求 12–128 字符，邀请码管理员通过终端隐藏输入，要求 16–128 字符。没有默认凭据、明文邀请码环境变量或网页管理接口。
- 邀请码剩余次数与新增用户在同一 SQLite 事务中提交；更换立即生效，可关闭注册，另有全站账号上限。
- 登录成功生成随机会话，数据库仅存令牌 SHA-256 摘要；Cookie 使用 HttpOnly、SameSite=Strict，server 额外使用 Secure。12 小时绝对过期，最多保留 5 个设备会话。
- 写入必须携带对应会话的独立 CSRF token，同时检查 Host / Origin / Sec-Fetch-Site；登录注册要求 JSON 与自定义请求头，不接受跨域请求。
- 注销删除会话；密码重置删除该用户全部会话。不存在的用户也执行一次密码哈希校验，登录错误统一回复。
- 同一浏览器共享 Cookie；切换会刷新其他标签页，并清除当前页面草稿。已开始的后台模型请求可能继续到超时，只能访问原账号的数据。

## 限流与资源

SQLite 持久化限流计数，重启不会清零。认证全局 60 次/10 分钟、每 IP 12 次/10 分钟、每用户名 15 次/10 分钟；注册另限每 IP 5 次/小时和全局 20 次/天。成功和失败都计数，宁可暂时关闭注册，也不无限消耗密码哈希资源。最多 5000 个未过期限流键，满后拒绝新键。

认证哈希同时仅执行一次。每账号业务请求 240 次/分钟，AI 操作 12 次/分钟。全局模型操作和后台识别共享 2 个实际执行槽，取消等待不会提前释放资源。完成任务最多缓存 128 个、15 分钟过期。

Waitress 限制线程、连接、请求头及请求体；Nginx 限流、限制连接和上传超时、先缓冲请求再交给应用；WSGI 流式队列有上限，客户端停止读取不会无限堆积。模型普通响应和 SSE 限大小，SSE 另有时间检查。外部请求读取超时不代表整个多轮 Agent 的总耗时上限，长任务仍会占用两个槽之一。

2 GB 配置的上传、导出、磁盘和 systemd 限制见部署指南。文件配额是写入前检查，不是事务性的文件系统硬配额；一次允许的请求和备份可能超过阈值。需监控磁盘和日志。限流无法完全防止分布式攻击或带宽 DDoS，也不能保证攻击期间服务仍可用。

## SSRF、内容与传输

server 的模型地址只能使用管理员设置的**精确 HTTPS 来源白名单**；Tavily 使用固定地址。每次出站请求均重新检查，关闭环境代理与 HTTP 重定向。DNS 解析后拒绝任何非公网地址（包括私网、回环、link-local、阿里云元数据地址），连接到已验证的 IP，同时保留原域名用于 TLS 校验和 SNI，避免校验后再次解析带来的 DNS rebinding。参见 [OWASP SSRF](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html)。管理员只能加入确实可信的服务商，白名单不应由普通用户修改。

SQL 使用参数化查询；照片格式、路径和上传体积有校验。前端对显示数据转义，外部来源链接只允许 HTTP(S)，使用 noopener / noreferrer。CSP 禁止外部脚本、内联脚本和嵌入框架；CSS 仍允许内联样式以支持现有图表。响应不缓存、禁止 MIME 嗅探。

公网必须使用 HTTPS。Nginx 覆盖 X-Real-IP 并清除转发头，应用只监听本机；服务器本机进程属于可信边界。业务服务以非 root 用户运行，代码只读，只有数据目录和私有临时目录可写。

显式启用 `FITAI_SSH_PREVIEW=1` 时，server 仅额外支持形如 `http://localhost:18765` 的私人预览来源，拒绝公网域名、IP 和特权端口。服务仍绑定服务器回环地址、保留 Secure Cookie 与邀请码门禁；电脑和 ECS 间的传输必须经过 SSH。此模式忽略客户端 X-Real-IP，不能通过公网反向代理发布。关闭该开关后恢复严格 HTTPS 来源要求。

## 尚未提供的保障

- API Key 和健康记录不是端到端加密：业务 Key 目前以明文存在受权限保护的数据库，服务器管理员或拿到备份的人可以读取。邀请码/密码不可逆哈希并不意味着整个数据库加密。
- 没有邮件验证、邮件找回、MFA、验证码或完整审计后台。受邀账号应来自可信使用者；丢失密码由管理员重置。
- 本配置仅支持单进程单机；全局并发控制和后台任务保存在内存，不应启动多个副本。重启会丢失未完成识别任务，但不会丢失已提交记录。
- SQLite 自动快照只覆盖该用户数据库，不等同于整站照片一致性备份；使用提供的停机备份脚本做完整备份。
- 测试覆盖重要访问控制与回归路径，不等同于独立渗透测试、真实 ECS 压测或“抵御一切攻击”。上线前需验证域名、TLS、反向代理、权限、备份恢复与真实模型网络。
